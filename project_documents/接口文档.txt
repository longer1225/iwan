Iwan博客项目-全局API接口规范文档（V1.0）
1. 文档概述
1.1 文档目的
本文档为 Iwan个人社交博客系统 后端统一API接口开发规范，用于统一前后端交互标准、统一编码风格、统一返回结构、统一异常与分页规则。
所有业务接口、管理员接口、文件接口、AI预留接口、WebSocket交互接口全部遵循本规范，保证项目可维护、可迭代、可无缝扩展AI能力、团队协作统一。
1.2 适用范围
Iwan项目所有HTTP/HTTPS业务接口、文件上传接口、后台管理接口、AI扩展接口、回调接口。
1.3 设计原则
•	遵循 RESTful 接口语义规范
•	统一入参、统一出参、统一状态码、统一异常信息
•	接口分层解耦，支持后续新增模块、新增AI功能无缝接入
•	严格权限控制、参数校验、防重复、安全合规
•	所有接口预留扩展字段，适配长期迭代
2. 基础全局规范
2.1 项目基础信息
项目名称：Iwan 个人社交博客系统
接口协议：HTTP / HTTPS
数据编码：UTF-8
数据格式：JSON
2.2 全局接口前缀（固定）
为区分业务模块、管理模块、AI模块，全局统一三套前缀，彻底解耦，方便后续权限隔离、路由分发、版本迭代。
•	前台用户业务接口：/Iwan/api/v1/
•	后台管理员接口：/Iwan/api/admin/v1/
•	AI智能扩展接口：/Iwan/api/ai/v1/
优势：后续可独立扩展 v2 版本、独立拆分AI服务、独立管控后台权限，互不冲突。
2.3 HTTP请求方法规范（RESTful）
严格限定请求方式，语义统一，禁止乱用请求方法。
请求方法	语义	使用场景
GET	查询、读取	获取列表、详情、统计、公开数据，禁止写操作
POST	新增、提交	新增数据、发布内容、登录注册、复杂提交
PUT	全量更新	完整更新一条数据、编辑全部内容
PATCH	局部更新	更新部分字段（状态、权限、配置）
DELETE	删除	逻辑删除/物理删除数据
2.4 URL命名规范
•	全部采用 小写字母 + 下划线
•	资源名词复数形式，语义清晰
•	禁止拼音、禁止乱缩写、禁止大小写混合
示例：
•	正确：/Iwan/api/v1/articles 获取文章列表
•	正确：/Iwan/api/v1/friends 获取好友列表
•	正确：/Iwan/api/ai/v1/chat/session AI会话操作
3. 全局统一返回格式（核心规范）
所有接口必须返回统一JSON结构，无特例，方便前端统一拦截、统一提示、统一异常处理。
3.1 统一返回结构体
json
{
  "code": 200,
  "msg": "请求成功",
  "data": {},
  "extend": {}
}
3.2 字段详细说明（含扩展设计）
•	code：业务状态码，前端判断成功/失败的唯一依据
•	msg：返回提示信息，用于前端展示文案
•	data：主体业务数据，成功时返回具体内容，失败返回null/空
•	extend：全局预留扩展字段，用于存放附加信息、版本信息、AI参数、日志ID、权限标识、追踪ID，后续新增功能无需改返回结构
4. 全局状态码规范
区分 HTTP状态码 和 自定义业务状态码，前端只识别业务码，语义清晰、便于排查问题。
4.1 业务状态码清单
业务码	含义	使用场景
200	成功	所有正常请求返回
400	参数错误	入参缺失、格式错误、参数非法
401	未登录 / Token失效	未鉴权、令牌过期、令牌伪造
403	权限不足	登录但无访问权限、内容私密无权查看
404	资源不存在	文章已删除、用户不存在、记录不存在
409	业务冲突	重复操作、好友已存在、重复点赞
429	请求频繁/限流	接口限流、防刷控制
500	服务器异常	程序报错、数据库异常、中间件异常
600+	AI模块自定义错误	AI超时、向量检索失败、模型调用异常（预留区间）
5. 统一分页规范（全局通用）
所有列表查询接口统一分页结构体，杜绝五花八门的分页格式，预留排序、扩展参数。
5.1 分页入参
json
{
  "pageNum": 1,
  "pageSize": 10,
  "sortField": "create_time",
  "sortOrder": "desc",
  "filter": {}
}
•	pageNum：页码，默认1
•	pageSize：每页条数，默认10，最大限制50
•	sortField：排序字段，默认创建时间
•	sortOrder：排序方式 asc/desc
•	filter：预留扩展筛选对象，所有模糊查询、条件查询全部放入filter，无需新增参数
5.2 分页出参
json
{
  "code": 200,
  "msg": "请求成功",
  "data": {
    "total": 100,
    "pages": 10,
    "current": 1,
    "size": 10,
    "records": [],
    "pageExt": {}
  },
  "extend": {}
}
•	total：总条数
•	pages：总页数
•	current：当前页
•	size：每页大小
•	records：数据列表
•	pageExt：分页扩展字段，用于返回聚合数据、统计数据、附加参数
6. 统一请求头规范
6.1 必须携带请求头
•	Authorization：用户登录Token，格式：Bearer token值
•	Content-Type：默认 application/json;charset=UTF-8
未登录访客接口无需携带Token，后端自动适配匿名身份。
7. 特殊接口规范
7.1 文件上传接口规范
•	请求方式：POST
•	Content-Type：multipart/form-data
•	统一返回：文件URL、文件名、文件大小、文件类型、上传时间
•	支持单文件、多文件批量上传
•	后端统一校验：文件类型、大小、恶意文件拦截
7.2 WebSocket实时通信规范
用于即时聊天、实时状态推送，统一消息格式：
json
{
  "type": "chat|notice|status",
  "fromUserId": "",
  "toUserId": "",
  "content": "",
  "time": "",
  "wsExt": {}
}
wsExt 预留扩展，适配后续表情包、已读回执、消息撤回等功能。
7.3 AI接口专属规范
AI接口统一前缀 /Iwan/api/ai/v1/，单独做限流、超时、重试策略：
•	所有AI对话、RAG检索、内容生成统一走AI网关
•	返回体保留 stream 流式标识，支持流式输出与普通返回兼容
•	统一携带model版本、token消耗、耗时信息放入extend
•	预留AI功能灰度、权限、付费控制字段
8. 全局扩展设计（重点）
本接口规范全部预留扩展能力，完全适配Iwan项目长期迭代：
•	统一 extend 顶层扩展字段：支持全局附加参数，无需改结构
•	分页 filter/pageExt：支持无限新增筛选条件、分页统计
•	AI独立路由前缀：后续可微服务拆分、独立部署AI模块
•	业务码预留600+区间：专门用于AI异常、智能功能异常
•	WebSocket消息预留wsExt：适配聊天功能持续迭代
•	所有入参不写死固定字段，支持JSONB动态业务适配
9. 接口开发强制约束
•	禁止私自修改返回结构，所有接口必须遵守统一模板
•	所有新增功能优先使用扩展字段，禁止随意新增顶层参数
•	所有查询类接口默认开启分页，防止大数据量溢出
•	所有写操作必须做参数校验、权限校验、防重复提交
•	异常统一捕获，禁止直接抛出原生错误信息到前端
